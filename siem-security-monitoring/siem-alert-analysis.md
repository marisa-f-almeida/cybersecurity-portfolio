# SIEM Alert Analysis

## 🔎 Alert Investigation

This document analyzes the security alert generated by the simulated SIEM environment.

The purpose of the investigation is to determine whether the observed events represent potentially unauthorized activity and to identify the appropriate next steps.

## 🚨 Alert Summary

**Alert:** Suspicious Administrative Account Activity

**Severity:** High

**Affected Host:** `FILE-SRV-01`

**Account:** `admin`

**Source IP:** `185.220.101.45`

**Status:** Open

## 📊 Observed Events

The following sequence was identified:

1. Five failed login attempts against the `admin` account.
2. A successful login from the same external IP address.
3. Privilege escalation shortly after authentication.
4. Sensitive file access shortly after privilege escalation.

### Event Sequence

| Event                 | Observation                                 | Risk   |
| --------------------- | ------------------------------------------- | ------ |
| Failed Login #1       | Authentication failed                       | Low    |
| Failed Login #2       | Authentication failed                       | Low    |
| Failed Login #3       | Authentication failed                       | Medium |
| Failed Login #4       | Authentication failed                       | Medium |
| Failed Login #5       | Authentication failed                       | Medium |
| Successful Login      | Same external IP authenticated successfully | High   |
| Privilege Escalation  | Elevated privileges detected                | High   |
| Sensitive File Access | Sensitive resource accessed                 | High   |

## 🧠 Correlation Analysis

The individual failed login events may not be sufficient to identify an incident.

However, the events become significantly more suspicious when correlated:

**5 Failed Logins**

↓

**Successful Administrative Login**

↓

**Privilege Escalation**

↓

**Sensitive File Access**

This sequence suggests that the account may have been compromised or misused.

The available evidence does not independently confirm compromise, so additional investigation is required.

## 🚩 Indicators of Compromise

### Source IP

`185.220.101.45`

The same external IP address was associated with the failed login attempts and subsequent successful authentication.

### Account

`admin`

The administrative account experienced repeated authentication failures followed by successful authentication.

### Privilege Escalation

Privilege escalation occurred immediately after the successful login.

This event increases the potential impact of the activity.

### Sensitive File Access

Sensitive files were accessed shortly after privilege escalation.

This may indicate unauthorized access to protected information.

## 🔍 Investigation Questions

The analyst should determine:

* Was the `admin` login authorized?
* Who normally uses the `admin` account?
* Was the source IP expected or trusted?
* Was the account password recently changed?
* What process performed the privilege escalation?
* Which files were accessed?
* Were files modified, copied, or deleted?
* Did the same IP address access other systems?
* Were other accounts targeted?
* Are there related endpoint security alerts?

## 🛡️ Recommended Investigation Steps

### Step 1 — Validate Authentication

Review authentication logs to determine whether the successful login was legitimate.

### Step 2 — Investigate the Source IP

Search the SIEM for additional events associated with:

`185.220.101.45`

### Step 3 — Investigate Privilege Escalation

Review endpoint and operating system logs to determine how elevated privileges were obtained.

### Step 4 — Review File Access

Identify which sensitive files were accessed and determine whether the activity was authorized.

### Step 5 — Search for Related Activity

Search the SIEM for:

* Additional failed logins
* Successful logins
* Other affected accounts
* Other affected hosts
* Suspicious network connections

### Step 6 — Determine Scope

Identify whether the activity was isolated to one system or affected multiple systems.

## 🚨 Recommended Response

If unauthorized activity is confirmed:

1. Disable or restrict the affected account.
2. Reset the account credentials.
3. Revoke active sessions when appropriate.
4. Isolate the affected host if necessary.
5. Preserve relevant logs and evidence.
6. Block confirmed malicious indicators.
7. Investigate potentially affected systems.
8. Monitor for additional suspicious activity.
9. Document all containment and remediation actions.

## 📈 Severity Assessment

**Initial Severity: High**

The severity is high because the activity includes multiple suspicious authentication attempts followed by successful administrative access, privilege escalation, and sensitive file access.

### Severity could increase if:

* Malware is discovered.
* Credentials are confirmed compromised.
* Data exfiltration is identified.
* Additional systems are affected.
* Persistence mechanisms are discovered.

## 🧩 Analyst Decision

**Current Decision: Escalate for Investigation**

The alert should be escalated to the appropriate security response team for additional investigation.

The available evidence supports treating the activity as a high-priority security event, but it does not by itself prove malicious activity.

The combination of authentication failures, successful administrative access, privilege escalation, and sensitive file access represents a suspicious sequence requiring further investigation.
